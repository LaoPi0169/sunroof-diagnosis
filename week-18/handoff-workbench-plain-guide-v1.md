# 值守交接工作台 · 白话文操作手册 v1（第 18 周）

> 一句话：这个页面（http://127.0.0.1:8018）是给**两类人**用的——**业务用户**打开就能用，
> 不需要登录，也**看不到**任何配置；**管理员（值守）**必须登录后，才能看到并操作
> 注入故障、开关、回滚这些配置。这本手册用大白话讲清楚每一类人怎么用。

---

## 0. 开机（交付人做，一次）

1. 双击项目根目录的 `start_workbench_handoff.bat`。
2. 弹出的黑窗口保持开着（那是服务），浏览器会自动打开 http://127.0.0.1:8018。
3. 没自动开就手动在浏览器输入 `http://127.0.0.1:8018`。

页面上方有两个标签：**「业务用户」**（默认）和**「管理员 / 值守」**。

## 第一册 · 业务用户怎么用（不用登录）

### 1.1 你能做什么（页面「我能做什么」卡片里也写着）

- **问政策**：页面上有三个问题按钮，点一下就有答案。每个答案都会写
  「依据文档 + 版本」——比如「billing-general-v3 · v3 (2026 现行)」。
  **如果答案引用的版本写着「已废止」**，说明系统配置可能坏了，
  答案下面会出现一行黄色警告——这时候不要按那个答案对客户承诺，
  告诉值守的人就行。
- **办工单**：三步——①生成预览 → ②批准（或拒绝）→ ③执行创建。
  - 预览不产生任何真实效果；批准是「受控确认」；执行后页面会显示
    「累计外部效果」+1（这是真实发生的工单笔数）。
- **服务忙的时候**：如果页面顶部黄条说「工单通道暂时繁忙」，说明依赖出了故障，
  你的请求**已经安全存成待办预览，不会丢**。等黄条消失后点
  **「稍后重试（续跑同一任务）」**就能把刚才那单接着办完，不会重复建单。
- **想验证没重复建单**：点**「幂等重放」**——同一请求再发一次，
  页面会显示「对账通过：计数不变」。数字变了才需要喊人。

### 1.2 你不需要、也拿不到的东西

- 注入故障、开关、回滚、审计、发布清单这些**配置类按钮只存在于「管理员 / 值守」
  标签页**，而且必须登录。业务用户就算绕过页面直接调接口，服务端也只回一句
  「403 admin_required」——这不是页面藏得好不好，是服务端真拦。
- 你看不到别人的任务，也看不到内部遥测。你的任务在「我的任务」表里
  （任务号 / 类型 / 结果 / 外部效果）。

## 第二册 · 管理员（值守）怎么用（必须登录）

### 2.1 登录

1. 点顶部「管理员 / 值守」标签。
2. 填**值守代号**（比如 `值守-甲`）和**口令**。
3. 本教学模拟的固定口令是：`oncall-w18`。
   **诚实边界**：这是课程教学用的固定口令，写在手册里是为了你能登录；
   真实系统绝不会这样存口令——要用个人凭据、定期轮换、双人在岗。
   口令只用来比对：登录成败记录里只有代号和时间，**永远不记口令**。
4. 登录后才会出现配置面板；点「退出登录」或「重置环境」后面板会再次收起。

### 2.2 登录后你会看到的（从上到下）

| 区块 | 是什么 | 你会在什么时候用它 |
| --- | --- | --- |
| 现状总览 | 依赖是否降级、现行版本包是 rc-18.0（良好）还是 rc-18.1（含回归）、有没有任务停在待办预览 | 每次接手先看这一屏 |
| 封存故障包 | F-18.1（MCP 写通道不可达）注入/解除；F-18.2（配置回归）重埋/回滚 | 按下面的处置 SOP |
| MCP_OFF 开关 | 打开=隔离写通道；复位=按批准流程恢复 | 外部依赖故障时 |
| 理由输入框 | 开关和回滚都必须填理由，**空理由直接被拒绝** | 每次动作前 |
| 审计（四张表） | 开关 / 版本包 / 故障注入 / 登录，只增不改 | 复盘与留痕 |
| 发布清单 v2 | 六类绑定（代码/schema/语料索引/提示/策略工具/环境配置）+ 回滚目标 | 回滚前对一眼「整包」 |
| 恢复复验（四+1） | 一键重跑：正常查询 / 正确拒答 / 人工升级 / 逐次批准写入 / 重复请求对账 | **每次处置完必跑** |
| 任务追踪 | 任选任务看九阶段链（含降级段、引用版本段） | 判断「卡在哪一段」 |
| 重置环境 | 全部归零、所有人踢下线 | 演练结束/换场 |

### 2.3 处置 SOP 一：业务报「工单发不出去」（F-18.1 类，外部依赖故障）

1. **观察**：总览显示「降级中」；任务追踪里写任务停在 `action_preview`，
   原因 `mcp_unavailable`。
2. **归因**：外部依赖（MCP 写通道）不可达——**这不是我们发布的问题**。
3. **动作**：两条路任选——「注入解除」（故障消失时）或「打开 MCP_OFF 开关」
   （依赖持续坏时，把写通道隔离掉）。填理由再点。
4. **为什么**：开关的作用是**别再往坏通道上撞**；读和预览不受影响，
   业务侧看到的是「稍后重试」，没有丢单也没有重复单。
5. **复验**：等业务点「稍后重试」跑完（或看任务追踪 `action_completed`），
   再跑「恢复复验（四+1）」——**5 行全 pass 才算恢复**。只看服务活着不算数。

### 2.4 处置 SOP 二：答案权限版本不对（F-18.2 类，发布自身回归）

1. **观察**：业务问答引用了**废止版本**（比如 2025 年的 v1），页面上有黄色警告。
2. **归因**：现行版本包 rc-18.1 的**配置**把「现行口径」绑到了废止文档——
   这是**我们这次发布带进来的回归**，不是外部依赖。
3. **关键判断**：**关开关修不了这个**。开关只是隔离写通道，答案照样错。
   唯一正确动作是**回滚完整版本包**（整包退回 rc-18.0），不是只改一个文件。
4. **动作**：填理由 → 点「回滚完整版本包 → rc-18.0」。审计里会记下
   「从 rc-18.1 回滚到 rc-18.0 + 你的理由 + 时间」。
5. **复验**：业务再问一遍——引用恢复「billing-general-v3 · v3 (现行)」；
   跑「恢复复验（四+1）」→ 5 行全 pass（回滚前跑是 fail，这本身就是证据）。

### 2.5 演练怎么重开一轮

- 「重埋回归（挂回 rc-18.1）」把回归包重新挂上，供下一轮训练；
- 「重置环境」把任务/审计/会话全部归零（所有人要重新登录）。

## 常见问题

- **Q：我是业务用户，要不要登录？** 不用。打开就是你的页面；配置按钮根本不出现。
- **Q：口令忘了/输了三遍不对？** 教学口令见第 2.1 节；输错只记「登录失败+代号」，
  不会锁人。
- **Q：为什么我点开关没反应？** 理由框是空的——先填理由（无因操作未批准）。
- **Q：重置后我为什么被登出了？** 重置=回到交接初始态，所有会话作废，重新登录即可。
- **Q：页面脚本报红条？** 按提示换新版 Edge/Chrome 并 Ctrl+F5；还失败就联系交付人。

## 红线（NO-GO，出现任何一条本轮直接不及格）

1. **越权**：业务用户视角出现任何配置操作入口（服务端 403 是底线）；
2. **未批准写入**：没有受控确认就产生外部效果（预览必须先于执行）；
3. **秘密泄漏**：口令/token/客户字段出现在遥测、审计或页面展示里；
4. **无法回滚**：版本包动作没有留痕，或回滚后复验不过却宣布恢复。
