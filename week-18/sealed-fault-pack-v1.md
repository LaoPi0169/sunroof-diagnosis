## 案例 F-18.1：MCP 写通道不可达（外部依赖故障）

**注入方式**：管理面板 → 封存故障包 → 「F-18.1 注入」。
**现象面**（业务用户标签页可见）：工单执行停在「待办预览」黄条；
**内部面**（管理面板可见）：总览「降级中 (来源: fault_injection)」；
任务追踪：写任务九阶段链停在 `action_preview`，`reason_code=mcp_unavailable`。

值守应完成的判断与动作（评分点）：

| 步骤 | 合格标准 |
| --- | --- |
| 观察 | 读路径正常（问答仍 answered），只有写停驻 —— 说出「读不受阻」 |
| 归因 | 外部依赖故障，**不是发布回归** —— 明确说出「不回滚」 |
| 动作 | 「解除注入」或「打开 MCP_OFF 开关」，**带理由**（空理由被服务端拒绝） |
| 效果核查 | 停驻期间外部效果 0、审批未消耗、探测恰 1 次（不自动重试） |
| 恢复 | 解除/复位后让业务点「稍后重试」→ `action_completed` 恰 1 效果 |
| 复验 | 「恢复复验（四+1）」5 行全 pass + 幂等重放计数不变 |

**陷阱题（口试）**：如果值守此时选择「回滚版本包」，为什么是错的？
—— 回滚修不了外部依赖；发布本身没坏（手册 4034）。

## 案例 F-18.2：配置回归——废止政策被复活（发布自身回归）

**注入方式**：交接初始态即是（现行包 = rc-18.1，已埋回归）；或管理面板
「重埋回归（挂回 rc-18.1）」。
**现象面**：业务问答「华东差价」answered，但依据是
`billing-general-v1 · v1 (已废止)`，答案附黄色警告「疑似配置回归」；
**内部面**：总览版本包 rc-18.1 标红「配置回归 (F-18.2)」；
发布清单 v2 中 rc-18.1 的 env_config 现行绑定与 known-good 相悖。

值守应完成的判断与动作（评分点）：

| 步骤 | 合格标准 |
| --- | --- |
| 观察 | 正常问答引用废止版本；「恢复复验（四+1）」第 1 行 fail（其余 4 行 pass） |
| 归因 | 发布自身配置回归（现行口径绑定错），不是外部依赖 |
| 关键判断 | **关开关 ≠ 回滚**：开关只隔离写通道，答错的问题照旧错 —— 必须回滚 |
| 动作 | 「回滚完整版本包 → rc-18.0」**带理由**（审计记 from/to/operator/reason/at） |
| 整包意识 | 说出回滚对齐的是六类绑定（代码/schema/语料索引/提示/策略工具/环境配置），不是只改一个文件 |
| 复验 | 业务问答引用恢复 `billing-general-v3 (现行)` + 四+1 复验 5/5 pass |

**陷阱题（口试）**：回滚会清掉坏配置期间产生的工单吗？
—— 不会；审计与业务数据只增不改（诚实边界，见交接包「恢复能修什么/不能修什么」）。

## NO-GO 红线（任一出现 = 直接不及格，手册 4102-4104）

1. **越权**：业务用户视角出现配置入口，或值守绕过登录操作配置；
2. **未批准写入**：无受控确认的外部效果；
3. **秘密泄漏**：口令/token/客户字段进遥测、审计或展示；
4. **无法回滚**：动作无留痕，或复验不过却宣布恢复。
