# Option Note v1 —— 是否进入受限只读 RAG 语料治理

- **决定依据**: `data-application-stage-exit-v1.md` §4 的 [D]（允许只读 RAG 实验）+
  北辰探索简报版本 v1.0（未变更）
- **决定类型**: 模拟有权角色批准（课程内角色扮演，非真实客户批准）
- **本周边界**: 只做语料治理（来源/版本/权限/快照），不做 embedding 选型、
  不调向量检索、不生成回答、不写提示词、不运行正式 RAG 评测

## 四条路径比较

| 路径 | 能否解决「按角色给当前依据」 | 本周采纳 | 依据 |
| --- | --- | --- | --- |
| 普通搜索（共享盘关键字） | 部分能，但无版本/权限保证，过期文档同样命中 | 否 | 第 7 周一线走查已证实共享盘噪声导致 POLICY_CONFLICT 类事故 |
| 内容治理（不建检索，只清目录） | 能改善来源质量，但无法按角色出候选 | 部分吸收 | 治理合同本周照做，作为 RAG 前置而非替代 |
| 受限只读 RAG（先语料治理） | 有望，但必须先证明候选集合权限安全 | **是** | stage-exit [D] + 确定性基线（35/35 + CI 四阶段）可作对照 |
| 停止 | — | 保留为合格退出项 | 若回读发现来源合同无法建立，退回此选项 |

## 本周只做语料治理的边界（重申）

- 产物是**可重复构建、权限受控的语料快照**（`sunroof-corpus-w09-v1`），不是检索系统；
- 全程零模型调用：不做 embedding、不调检索、不生成回答、不写提示词；
- 「语料可被治理」**不外推**「RAG 会改善任务」——后者留给第 10–12 周冻结评测后的只读实验；
- 回读发现来源合同无法建立时，走「停止」路径并登记，不硬上 RAG。
