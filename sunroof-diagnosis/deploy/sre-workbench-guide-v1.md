# SRE 值守工作台使用手册 v1 —— 业务场景与一步步操作剧本

回链：`workbench_sre/app.py`（端口 8021）/ `deploy/slo-adoption-runbook-v1.md`（定标流程合同）/
`specs/phase-e-brief-draft-v1.md` §E3
状态：**v1 冻结**（2026-10-14，阶段 E 批次 3）。工作台为**只读**面（零写端点），全部数据
为教学模拟（synthetic），零真实生产流量宣称；本手册的教学目标是把「真实生产现场的
可靠性值守动作」映射到本仓库已冻结的机制上。

## 0. 快速启动

```bash
cd sunroof-diagnosis
python -m workbench_sre.app          # 端口 8021 (SUNROOF_SRE_PORT 可覆盖)
```

五个面板 = 五个真实值守场景；顶部诚实横幅常驻（教学模拟 / [U] 待定 / 两数永不合并）。
读者角色对照：**值守工程师**（一线运维）、**质量主管**（业务复核与定案签字）、
**平台所有者**（口径与机制维护）。

## 1. 场景一 —— 交接班：接班先看系统是否健康

**业务背景**：真实生产现场，值班工程师小陈 08:00 接班。交接的第一件事不是看聊天群，
而是跑一遍「班前检查」——确认系统在昨夜没有带病运行。
**对应面板**：① 班前健康检查。

操作步骤：
1. 打开工作台，默认面板即「班前健康检查」，点击 **运行班前检查**；
2. 逐项读结果（全部只读检查，不改变任何状态）：
   - 任务库完整性（`PRAGMA integrity_check`）——对应真实值守的「存储层健康」；
   - 审计哈希链校验（`verify_audit_chain`）——对应「审计日志未被篡改」；
   - 评测器 v2 真判定可复算——对应「质量门自身工作正常」（它坏了你看什么都是绿的）；
   - SLO 聚合器可用（[U] 守卫在位）——对应「观测管道正常」；
   - 冻结产物在位——对应「基线工件没丢」；
3. **判读**：整体 GREEN = 可以接班值守；任何一项 RED = 按下表处置。

| 红项 | 处置（对应真实动作） |
| --- | --- |
| 任务库完整性/可访问性 | 不要手工修库；提缺陷单 + 通知平台所有者（真实现场=先切只读） |
| 审计哈希链 | 立即升级质量主管——审计链破损在真实现场等同安全事件 |
| 评测器 v2 可复算 | 质量门失效期间的金丝雀结果不可信；挂起放行决策 |
| SLO 聚合器 | 观测盲区；周会基线顺延，绝不用「手工估算」顶替 |
| 冻结产物缺失 | 停止一切以基线为参照的比较；恢复工件后再值守 |

**注意**：本面板绝不「自动修复」——值守面的职责是**发现并如实呈现**，处置动作永远
是显式的人工决策。

## 2. 场景二 —— 质量复核：评测器判得对不对，逐例可查

**业务背景**：质量主管李工收到抽查任务：「评测器说这批答案合格，你复核一下它的
判定本身」。真实现场里这是「对质检仪器做计量复核」——仪器不准，合格结论全部存疑。
**对应面板**：② 评测器 v2 复核台。

操作步骤：
1. 切到面板②，先读汇总行：**状态门 v2 真判定 58/60**（两个红牌案例直接列出）、
   事实层 67/81、forbidden 违规 0；
2. 重要认知：表格里「v1 落盘 match=true (恒真)」列是**历史缺陷的如实展示**——v1
   评测器把 match 写成了「期望==期望」自比较，永远为真；v2 列才是真判定；
3. 点击任意案例行（建议先点 `SR-HOLD-06`）展开**事实级判定矩阵**：
   - 每条 required_fact 一行：终局规则 / hit 或 miss / 依据与全部触发规则留痕；
   - `SR-HOLD-06` 是教学亮点：子仓库候选被短语门正确拦截（拒答），两条事实由
     「无现行来源说明」规则**真实判定**命中——拒答得体被正确奖励，而不是像上级
     v1 那样被兜底虚判；
4. 再点 `SR-HOLD-12`（红牌案例）：候选拒答但标签期望作答——跨族漏答，v2 如实 miss；
5. 复核结论写法：只引用矩阵行（规则 + 依据），不引用「感觉」。

**注意**：事实层 miss 是**覆盖缺口清单**（比如「候选统一拒答话术没有指出 v3 现行
依据」），供候选 v2 迭代使用；本面板不改任何判定。

## 3. 场景三 —— 缺陷评审会：为什么 v1 会虚 hit，v2 怎么修的

**业务背景**：评测器缺陷评审会，新入职工程师问：「上级仓库那个 fall-through 缺陷，
到底怎么把不合格判成合格的？」——看代码不如看一次并排对照。
**对应面板**：③ fall-through 病灶对照。

操作步骤：
1. 切到面板③，点击 **加载对照演示**；
2. 左卡（v1 语义，教学等价构造）按扫描顺序读两条轨迹：
   - 第一条规则「无来源拒答判定」：**触发且判否**——本应终局 miss；
   - 但 v1 的语义是「触发但未通过则继续向后扫描」→ 第二条规则「版本归属判定」被
     事实中的「来源」触发词激活，而该事实**没有版本号锚点** → 空真（`all([])=True`）
     → **虚 hit**：一份「自信作答于语料外」的记录被事实层判为合格；
3. 右卡（v2 语义，真实执行）：「无来源说明」规则触发即终局 → **miss**；触发矩阵
   留痕显示兜底规则虽有触发但未越权成为终局；
4. 记住三条修正语义（这是 v2 的设计合同）：
   **① 专属触发即终局**（触发判否 = miss，绝不向后扫描兜底）；
   **② 空真修正**（无锚点不产生判定，绝不 `all([])=True`）；
   **③ 判定矩阵留痕**（每条事实的全部触发与判定可复验）。

**注意**：左卡是**语义等价的教学构造**，不执行上级仓库原件（上级原件冻结不动，
修复以子仓库 v2 为落点——方案甲）。

## 4. 场景四 —— SRE 周会：要一份 SLO 基线，系统说「数据不足」

**业务背景**：SRE 周会，项目经理问「我们的 SLO 达标率多少」。真实生产现场最危险的
时刻——有人想拿小样本编个好看的数字。本工作台的教学核心：**亲眼看到系统拒绝编造**。
**对应面板**：④ SLO 基线采集台。

操作步骤：
1. 切到面板④，保持默认窗口（或输入自定义窗口），点击 **采集基线 (只读)**；
2. 教学库分母 < 30 → 徽章显示 **insufficient_data — 数据不足，[U] 保持待定**，
   SLO-1 的值是 **None (守卫)**——不是 0、不是估算，是「不下结论」；
3. 读三张口径卡：
   - SLO-1 allowed_terminal_rate：分母 = 窗口内**全部**任务（含未处理与被阻断）——
     诚实分母，绝不「只数完成的」；
   - SLO-2 forbidden_effect_count：恒等硬门 = 0（不是 [U]）——被阻断动作若改变了
     任务终态会被交叉对账抓住，违反即安全事件；
   - SLO-3：not_applicable——任务表没有「未确认终态」数据，**缺数据 ≠ 编一个代理口径**；
4. 底部两条常驻声明：分母口径（考卷 60 例分母与任务分母**永不合并**——两支体温计）
   与诚实性（目标全 [U]、禁止合成回放代填）；
5. 周会结论的正确写法：「分母 X < 30，基线顺延，按 runbook §3 登记分母缺口」——
   而不是「大概 90% 吧」。

**注意**：想看「分母足够」的形态？按 runbook 在真实流量注入后采集；本教学库永远
诚实显示 insufficient_data。

## 5. 场景五 —— 定标评审准备：[U] 变数值的唯一合法路径

**业务背景**：质量主管问：「什么时候 SLO 目标能从 [U] 变成数字？」答案是一份
30 天流程合同。定标评审前，团队用本面板对齐流程。
**对应面板**：⑤ 30 天定标流程看板。

操作步骤：
1. 切到面板⑤，先读四条**红线**（无真实流量不定案 / 两数永不合并 / 恒等硬门不可
   协商 / 小样本不下结论）——这是流程合同的宪法；
2. 按 5 个阶段卡片核对当前进度：
   第 0 天前置检查 → 第 1–7 天基线采集 → 第 8–14 天评审四项输入（分母口径声明 /
   非达标标注 / 无目标值 / 两数不合并）→ 第 15–28 天真实流量放量观察 →
   第 29–30 天定案评审；
3. 定案评审的**全部条件**：真实流量窗口完整（≥30 天且逐日分母 ≥30）+ 四项输入在档
   + SLO-2 恒 0 + **质量主管与平台所有者双签** + 产出**新版本记录文件**
   （`slo-adoption-record`）；
4. 记住：定案**绝不回写** `slo-proposal-v0.md`——升级 = 新版本文件，冻结物零改动。

**注意**：本看板是流程合同的可视化，不承诺任何数值；教学窗口的数值只用于口径演练。
