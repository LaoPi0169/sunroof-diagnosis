# Discovery Brief v1（问题合同与范围界定）—— 天窗总成只读诊断
版本 v1 · 阶段 A 节点 ①（W1-4 交付）· 状态：已获准（课程模拟走查）
回链：`specs/business-background.md` · `specs/role-and-permission-matrix.md` · `adr-001-deterministic-baseline.md`

## 1. 问题一句话
为天窗总线 PQE 提供一个**只读**的跨系统（MES/QMS/PLM）数据调取与对账入口，用 ACL 隔离跨主机厂敏感图纸，并在数据缺失、SOP 过期或来源冲突时明确拒答，最终输出一份带精确引用的《天窗总成异常根因分析报告》草稿供 PQE 参考核对。

## 2. 主要角色与触发条件
- **主要角色**：天窗总线 PQE（质量工程师）；裁决角色：质量主管。
- **触发条件**：EOL 台架报出「异响」或「防夹功能误触发」故障，或接到 OEM 主机厂市场退返件条码（SN）。

## 3. 交付范围（In-Scope）
1. 根据天窗 SN，通过只读通道自动抓取该 SN 在 MES 中的装配扭矩、ECU 刷写与传感器波形（阶段 C 以只读 MCP 工具实现）；
2. 匹配 QMS 中当前有效的检验 SOP、质量标准及 PLM 中的 BOM/ECO 工程变更版本；
3. 输出结构化、带出处引用的《天窗总成异常根因分析报告草稿》。

## 4. 非目标（Out-of-Scope，系统级禁止）
- **绝不**在 MES/QMS 中自动创建返修单、隔离单或报废单（外部写效果 = 0）；
- **绝不**自动向主机厂发送 8D 报告；
- **绝不**跨 OEM 客户授权展示图纸与敏感参数。

## 5. 保护指标（硬阻断门槛，可测量）
| # | 指标 | 门槛 | 验证方式 |
|---|---|---|---|
| P-1 | 跨 OEM 敏感图纸越权泄露 | **0 次** | ACL SQL 下推 + 零泄漏断言（响应体不含其他项目组标识） |
| P-2 | 引用过期/已被替代 SOP | **0 次** | `is_current=0` 行在 SQL 层被排除；测试断言被替代版本标识不出现在响应中 |
| P-3 | 数据缺失/冲突时假装知道 | **0 次** | 100% 触发 `needs_review`（阶段 A）/ `abstained`、`escalate`（后续节点），结构化 `reason_code` |

## 6. 成功判据（阶段 A 节点 ② 可验收口径）
- 合法 PQE 提交（SN、零件、工序、实测值、测量日期）→ `answered` + 唯一现行有效规格的出处（spec_id/版本/来源/公式）+ 偏差计算；
- 偏差超硬限（>15%）→ `needs_review/SPEC_HARD_LIMIT_EXCEEDED`，响应不含任何规格内容；
- 查询日期落在已替代版本窗口 → `needs_review/NO_MATCHING_SPEC`，绝不引用旧版；
- 同零件同工序两条现行规格 → `needs_review/SPEC_CONFLICT`；
- 跨项目组查询 → 拒答且**零泄漏**；缺字段 → 422；未知身份 → 401 且不落库；
- 每次请求在 `task_runs` 留痕，API 响应 / DB 终态 / 测试三方对账一致。

## 7. 风险与开放问题
| # | 风险/开放问题 | 处置 |
|---|---|---|
| R-1 | 历史测量日期落在旧规格窗口时，按「生产时点规格」还是「现行规格」判定？ | 决策：**只依据现行有效规格作答**，否则拒答转人工（保护指标 P-2 优先）；记录于行为合同 |
| R-2 | MES 波形数据量大，接口契约如何分页/裁剪？ | 阶段 C MCP 工具 schema 冻结时处理，阶段 A 不涉及 |
| R-3 | 冲突裁决需要质量主管 SOP | 记录为流程开放问题，`needs_review` 预览只给入口不给正文 |
| R-4 | 真实系统只读凭证治理 | 教学模拟以静态 Token 映射；上线前需重新评审权限矩阵 |
