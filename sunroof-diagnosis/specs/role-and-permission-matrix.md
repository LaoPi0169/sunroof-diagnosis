# 角色与权限矩阵（Role & Permission Matrix）—— 天窗总成只读诊断
版本 v1 · 阶段 A 节点 ①（W1-4 交付）· 状态：现行有效
回链：`specs/discovery-brief-v1.md` 非目标三条 · `specs/business-background.md` §3/§4 · `fde-roadmap-v1.md` §2 节点 ①

> 原则：身份只来自服务端可信会话（`X-Auth-Token`），请求体自报角色一律 `422`；矩阵未显式列出的 (角色, 对象, 动作) 组合一律默认拒绝（Default-Deny）。

## 1. 角色定义
| 角色 | role 值 | 项目组范围（allowed_oem_projects） | 说明 |
|---|---|---|---|
| PQE（项目组内） | `pqe` | `["OEM-A"]` 或 `["OEM-B"]`（按其所属项目组签发） | 天窗总线质量工程师，本系统唯一日常用户 |
| 质量主管 | `quality_supervisor` | `["*"]`（跨项目只读） | 特批例外与冲突裁决人；批准动作仍在原系统人工完成 |
| 系统/运维 | `ops` | 无业务数据读取 | 仅部署、回滚、看日志，不读业务正文 |
| 未知 / 未认证 | — | — | 401 默认拒绝，不执行查询、不落库 |

## 3. 服务端实现映射（阶段 A 节点 ② 已落地的部分）
| 矩阵条款 | 实现点 |
|---|---|
| 身份不来自请求体 | `application/auth.py`：仅 `X-Auth-Token` → 可信身份；`extra="forbid"` 使自报 role/身份字段 422 |
| 未知身份默认拒绝 | 未注册 Token → 401，不执行查询、不写审计 |
| ACL 项目组隔离 | `query_current_specs` SQL 下推 `oem_project IN (allowed_oem_projects)`；主管 `["*"]` 跨项目只读 |
| 跨项目零泄漏 | 拒答路径响应体只回显请求者自己的输入与通用常量，不含其他项目组的任何标识 |
| 外部写效果=0 | 全链路仅追加 `task_runs` 审计行，无任何业务状态修改 |

## 4. 已知边界（诚实标注）
- 真实 SSO / 统一身份未接入：教学模拟用静态 Token 映射可信身份；
- `escalate`（权限不足安全升级且不泄露受限文档名称）在 W13/W21 节点实现，阶段 A 先以 `needs_review` + 复核预览承载；
- 质量主管跨项目只读为**模拟授权**，真实环境需按最小权限重新评审本矩阵。
