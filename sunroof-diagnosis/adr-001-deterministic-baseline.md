# ADR-001：阶段 A 先交付确定性基线（零大模型），模型层后置
状态：已接受 · 日期：2026-10-10 · 回链：`fde-roadmap-v1.md` §2 节点 ② · `specs/discovery-brief-v1.md`

## 背景
《天窗总成异常根因分析报告》的最终形态涉及大模型生成与 RAG 检索；但本业务的三条硬阻断门槛（跨 OEM 越权 0 次、过期 SOP 引用 0 次、缺失/冲突时假装知道 0 次）若在无确定性地基时就引入生成层，将无法归因与验证。

## 决策
1. 阶段 A 节点 ② 只交付**确定性垂直薄片**：`POST /api/v1/spec-check`，判定 100% 由代码 + SQL 完成，零大模型调用、零外部写副作用；
2. `answered` 的语义冻结为「依据充分，可出具带引用草稿」，**不是**「合格」——合格与否（`conformance`）只是证据字段；
3. 缺失、冲突、超硬限一律显式 `needs_review` + 结构化原因码，禁止默认值填充与假成功；
4. 身份只来自服务端可信会话，ACL（`allowed_oem_projects`）在 SQL 层下推，阻断路径响应体零内容泄漏；
5. 生成层（RAG + 引用校验 + abstained/escalate 终态）留待后续节点，且必须构建在本合同冻结的地基之上。

## 后果
- 正面：三条硬门槛在第一阶段即可被自动化测试证明；报告的每条证据都可追溯到 spec_id/version/source_ref；
- 代价：历史测量日期落在旧规格窗口时宁可拒答（见行为合同边界 B-1），牺牲部分「聪明」换取 P-2=0；
- 复用：判定分支结构（硬限→零匹配→冲突→唯一命中）与审计三向对账模式可直接迁移给后续生成层做门禁。

## 备选方案（已否决）
- **方案 B：先搭 LLM 报告生成再加校验**——否决：无法在无确定性参照的情况下证明「0 幻觉」，泄露与过期引用风险不可归因；
- **方案 C：直接对接真实 MES/QMS/PLM**——否决：无真实凭证与授权，教学模拟先冻结合同与行为。
