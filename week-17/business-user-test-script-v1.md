## 0. 你在测什么（一分钟版）

依赖坏了的时候（模型超时 / 索引过期 / MCP 写通道不可用），合格的系统要
**停在明确、权限安全、可以继续人工处理的位置**，而不是报一屏红字，更不是
装作没事继续跑。本周重点验证 **MCP 不可用**：任务停在 `action_preview`
（预览保留、尚未创建）、外部效果 0、绝不自动重试写；恢复后用同一任务编号
续跑，效果**恰 1**、绝不重复。

## 1. 交付人操作（一次性，业务用户不执行本节）

1. 拿到整个项目文件夹（含 `.venv`）。
2. 双击项目根目录的 `start_workbench_degradation.bat` → 黑色窗口保持开着。
3. 约 2 秒后浏览器自动打开 `http://127.0.0.1:8017`；看到标题
   「依赖故障安全降级 —— 注入 × 关闭开关 × 恢复复验（第 17 周交付）」即启动成功。

（备选启动：`python -m uvicorn workbench_degradation.app:app --host 127.0.0.1 --port 8017`）

注意：服务只监听本机 127.0.0.1；单用户教学会话，多人测试请轮流使用。

## 3. 正常对照组 W-01（先证明平时是好的）

- **操作**：① 生成预览 → ② 批准（受控确认）→ ③ 执行创建。
- **预期**：预览后绿条「预览已生成（零效果）」且工单总数不变；
  执行后绿条 `action_completed：工单 SIM-5xxx 已由 ticket.get 独立核验（效果 +1）`，
  工单总数 0 → 1。
- **通过判据**：预览零效果；完成必须带独立核验，不由按钮自己宣称。

## 4. 故障路 A · 注入 W-02（演练手段）

- **操作**：注入故障 → ① 生成预览 → ② 批准 → ③ 执行创建。
- **预期**：
  1. 顶部黄色横幅「降级模式生效中（fault_injection）」；
  2. ③ 执行后**橙色**提示「停在 action_preview（mcp_unavailable）：外部效果 0，
     审批未消耗」；
  3. 页头工单总数**不变**；「最近一次结果」JSON：`degraded=true`、
     `reason_code=mcp_unavailable`、`allowed_next_actions` 三项、
     `external_effect_count=0`；
  4. 出现「可复制预览」框（copy_preview -> submit_manually 的人工通道）。
- **通过判据**：无「工单编号/创建成功」字样；零效果；一次执行只有一次尝试
  （无重试闪烁）。

## 5. 故障路 B · 关闭开关 W-03（运营手段）

- **操作**：打开开关 MCP_OFF → ① 生成预览 → ② 批准 → ③ 执行创建；
  再试负例：② 选「拒绝」→ ③ 执行。
- **预期**：降级结果与 W-02 完全一致（两条路同一终态）；「开关审计」表新增
  opened 行（含操作人/理由/时刻）；负例得到红条 `approval_required`
  （权限拒绝保持拒绝）。
- **通过判据**：开关不吞权限错误；审计逐条留痕。

## 6. 恢复复验 W-04（手册 3971-3978 六检查的浏览器版）

- **操作**：解除注入 + 按批准复位 MCP_OFF → 续跑同一任务（retry_later）→
  幂等重放 → 任务追踪选 `-retry` 与原始任务各看一次九阶段链 → 运行脱敏扫描。
- **预期**：复位后审计新增 closed 行；续跑绿条 action_completed 且工单总数
  **恰好 +1**；幂等重放后总数**不变**；原始任务 trace 的 mcp_call 段可见
  `mcp_unavailable` 与 `degraded=true`，retry 任务 trace 九段可还原；
  脱敏扫描「通过」。
- **通过判据**：效果恰 1、重放零重复、降级段与复验段同链可还原、日志干净
  ——「进程活着」不算数。

## 7. 三类固定演练 W-05

- **操作**：点「运行 8 段固定演练剧本」。
- **预期**：8 行全部 pass；D-01 模型超时 -> `system_failed`（效果 0）、
  D-02 索引过期 -> `abstained`（效果 0）、D-03/D-04 -> `action_preview`
  （效果 0）、D-05a/b -> `action_completed`（各 1）、D-05c -> `approval_denied`、

- **通过判据**：三类故障进预定义终态、无无限重试、效果合计恰 3。

## 10. 常见疑问

- 「橙色的 action_preview 是失败吗？」——它是**合格结果**：失败被诚实呈现、
  权限没扩大、单没开出去、下一步选项摆明。HTTP 200 加一段「工单已创建」
  才是失败结果。
- 「为什么我的批准没有作废？」——降级不消耗批准；恢复后续跑用的就是它。
  （深层故障场景例外，系统会用量如实入账并要求重新确认，幂等键保证不出
  第二张单。）
- 「注入和开关有什么区别？」——一个是演练者按的「模拟故障」按钮，一个是
  运营按的「真隔离」开关；对你的体验完全一样，审计里谁动的、为什么，全有记录。
