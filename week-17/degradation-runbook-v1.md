# 降级故障注入 Runbook v1（degradation-runbook-v1，第 17 周）

- 日期: 2026-10-09 · 目标读者: **没有参与开发的同事**（第 18 周冷交接前置：
  非作者按本 runbook 能独立复现故障 -> 降级 -> 恢复 -> 复验全程）
- 前置知识: 只需要浏览器 + 双击 bat；不要求读代码
- 全程约 10 分钟；所有操作都在隔离模拟环境，不产生任何真实外部效果

## 0. 你将复现什么

| 步骤 | 动作 | 预期结果 |
| --- | --- | --- |
| A | 启动降级工作台 | 浏览器打开 http://127.0.0.1:8017 |
| B | 正常对照组 | 预览 -> 批准 -> 执行 = action_completed，工单 +1 |
| C | 注入「MCP 不可用」再执行 | 停在 action_preview，效果 0，无重试 |
| D | 用关闭开关再复现一次 | 同一安全终态，审计留痕 |
| E | 恢复 + 复验 | 续跑恰 1 效果 + 幂等重放不变 + 受限任务仍拒绝 |
| F | 一键 8 段固定演练 | D-01..D-06 全 pass，含模型/索引两类 |

## 1. 启动（步骤 A）

1. 双击项目根目录 `start_workbench_degradation.bat`，黑色窗口保持开着；
2. 约 2 秒后浏览器自动打开 `http://127.0.0.1:8017`；
3. 页面顶部若出现红色横幅「降级模式生效中」，先点右上角「重置演示环境」。

（备选命令行: `.venv\Scripts\python -m uvicorn workbench_degradation.app:app --port 8017`）

## 2. 正常对照组（步骤 B）

依次点：**① 生成预览 → ② 批准（受控确认）→ ③ 执行创建**。
预期绿条 `action_completed：工单 SIM-5xxx 已由 ticket.get 独立核验（效果 +1）`，
页头「工单总数」从 0 变 1。若任何一步不是预期，停止并按 §6 报告。

## 3. 注入故障（步骤 C）

1. 点 **注入故障**（「故障注入」状态变为「已注入」，顶部出现黄色降级横幅）；
2. 再走一遍 **① 生成预览 → ② 批准 → ③ 执行创建**；
3. **必须看到**：橙色提示「停在 action_preview（mcp_unavailable）：外部效果 0，
   审批未消耗」；页头工单总数**不变**；「最近一次结果」JSON 里
   `degraded=true`、`allowed_next_actions` 三项；
4. **必须确认没有**：任何「创建成功/工单编号」字样（出现即为 P1 故障：
   降级路径伪造成功）；工单总数增加（即为 P0：降级路径携带效果）。

## 4. 关闭开关路径（步骤 D）

1. 点 **打开开关 MCP_OFF**（「开关审计」表新增一行 `opened`）；
2. 走 **① 生成预览 → ② 批准 → ③ 执行创建** —— 预期与步骤 C 完全相同
   （两条路、同一终态）；
3. （可选负例）② 选「拒绝」→ ③ 执行 —— 预期红条
   `approval_required`（权限拒绝保持拒绝，不被降级吞掉）。

## 5. 恢复复验（步骤 E）

1. 点 **解除注入（依赖恢复）** 和 **按批准复位 MCP_OFF**（审计表新增 `closed`）；
2. 点 **续跑同一任务（retry_later）** —— 预期绿条 `action_completed`，
   工单总数**恰好 +1**（从 0 到 1）；
3. 点 **幂等重放** —— 预期绿条「工单总数仍 1（无重复效果）」；
   **若总数变 2 即为 P0 故障（重复效果）**；
4. 打开「任务追踪」下拉，选带 `-retry` 的任务 → 点「查看九阶段链」——
   九段全部有值（缺席段标 n/a 不留空洞）；选原始任务可见降级段
   `mcp_unavailable`；
5. 点 **运行脱敏扫描** —— 预期绿色「通过」。

## 6. 一键固定演练（步骤 F）与报告

1. 点 **运行 8 段固定演练剧本** —— 预期 8 行全部 `pass` 徽章
   （D-01 模型超时 -> system_failed；D-02 索引过期 -> abstained；
   D-03/D-04 MCP 不可用 -> action_preview；D-05 恢复复验；D-06 对账回归）；
2. 把「最近一次结果」JSON 与演练表截图，连同页头工单计数一起存档
   （这就是你的演练证据）。

## 7. 异常处置与升级

| 症状 | 判断 | 动作 |
| --- | --- | --- |
| 页面红条「页面脚本异常」 | 前端脚本问题 | Ctrl+F5；仍失败 -> 换 Edge/Chrome -> 报告交付人 |
| 执行后出现工单编号但步骤 C/D 中 | **P1：降级伪造成功** | 立即「重置演示环境」，停止演练，报告（附「最近一次结果」JSON） |
| 恢复续跑后工单总数 +2 | **P0：重复效果** | 同上，最高优先 |
| 注入后执行直接红条 error | 检查是否误选「拒绝」/未批准 | 按 §3 重走（批准后再执行） |
| 800 端口/8016 端口服务无响应 | 与本工作台无关 | 本工作台独立于 8000（应用）与 8016（可观测性） |

## 8. 本 runbook 的边界

1. 演练对象是隔离模拟工单服务；真实系统的注入需要故障演练平台与审批；
2. 关闭开关的「批准」在本教学环境=填写操作人与理由（审计留痕）；
   真实系统需要双人在岗批准与冷静期（见 kill-switch-registry-v1.md §六）；
3. 恢复复验的判定永远看任务结果与效果计数，不是「进程活着」；
4. 若需命令行复现：`python -m mcptool.run_degradation_drill --out
   week-17/my-drill.jsonl`（退出码 0 = 8 段全过）。
