# 业务用户测试脚本 · 审批写工具交互工作台 v1

- 日期: 2026-10-08 · 对象: **业务用户**（全程只用浏览器，零命令行、零环境安装）
- 回链: `week-14/ticket-write-contract-v1.json` · `mcptool/demo_write_approval.py`（四次尝试对账）
- 交付物: `workbench_write/`（前台页面 + FastAPI 薄壳）+ `start_workbench.bat`
- 口径: 所有「工单」都发生在隔离模拟工单服务（SIM-5001 起编号），不触真实系统

## 0. 你在测什么（一分钟版）

政策冲突后，客服想给工单 NS-1042 创建一张主管复核单。系统的规矩是
「**写操作必须经过精确审批**」：

- 预览不产生任何效果；
- 只有**你本人批准**、且执行参数与批准内容**完全一致**、审批**未过期未用尽**，
  才会真的创建 1 张工单；
- 任何偏差（拒绝后执行 / 改参数 / 无审批 / 过期）都必须被拦截且**不产生效果**。

你的任务：按下面步骤亲手验证这些规矩，每一步都给出了精确的预期结果。

## 1. 交付人操作（一次性，业务用户不执行本节）

1. 拿到整个项目文件夹（含 `.venv`）。
2. 双击项目根目录的 `start_workbench.bat` → 弹出的黑色窗口保持开着（那就是服务）。
3. 约 2 秒后浏览器自动打开 `http://127.0.0.1:8014`；看到标题
   「主管复核单 · 审批写工具业务测试工作台」即启动成功。

（备选启动：`python -m uvicorn workbench_write.app:app --host 127.0.0.1 --port 8014`）

注意：服务只监听本机 127.0.0.1；这是单用户教学会话，多人测试请轮流使用同一页面。

## 3. 正向主流程 T-01..T-06

### T-01 生成预览（无副作用）

- **操作**：不改表单，点「生成预览」。
- **预期**：
  - 结果卡绿色：「预览成功：外部效果 0（工单总数不变）」；
  - 规范化参数表：`reason_code → POLICY_CONFLICT`（输入是小写 policy_conflict）、
    `source_refs → ["upgrade-east-v2","upgrade-notice-v4"]`（排序，输入是乱序）、
    `target_queue → billing-supervisor-review`（小写，输入是大小写混合）；
  - `resource_scope = case:NS-1042`；`expires_at ≈ 当前时间 + 15 分钟`；
  - 右侧：模拟工单总数**仍为 0**；受限审计链第 1 行 `ticket.preview_create → action_preview`。
- **通过判据**：三处规范化全部生效，且工单总数仍为 0。

### T-02 批准（签发逐次审批）

- **操作**：点「批准（签发逐次审批）」。
- **预期**：绿色「已批准：逐次审批已签发…」；记录 ID 以 `approval-run-w14-` 开头；
  使用额度 `0 / 1`；签发 → 过期时间相差 900 秒；绑定参数与 T-01 规范化参数一致。
- **通过判据**：右侧「当前审批状态」出现 approved 记录，额度 0/1。

### T-03 按审批执行（不改任何字段）

- **操作**：表单保持 T-01 原样，点「按当前审批执行」。
- **预期**：绿色「完成：已创建 SIM-5001（verified_by=ticket.get 独立核验）」；
  原始 JSON 里 `status=action_completed`、`idempotency_key={run_id}:ticket.create:1`、
  `external_ticket_count=1`；右侧：工单总数 **0 → 1**、累计外部效果 **1**、
  工单列表出现 SIM-5001（open · 队列 billing-supervisor-review · 请求人 user-zhou-ning）。
- **通过判据**：恰好创建 1 张，编号 SIM-5001。

### T-04 幂等重放（同一按钮再点一次，仍不改任何字段）

- **预期**：仍返回 **SIM-5001**；总数**仍为 1**；累计效果**仍为 1**；
  审批面板额度 `1 / 1`；审计链出现 `idempotent_replay`。
- **通过判据**：相同幂等键不产生第二个外部效果。

### T-05 改队列越权执行（审批绑定比对）

- **操作**：把 target_queue 改成 `executive-review`，点「按当前审批执行」。
- **预期**：红色「被拦截：approval_mismatch —— 审批与本次动作不匹配，已拒绝执行」；
  总数**仍为 1**、累计效果**仍为 1**；该行审计 `outcome=approval_mismatch`
  （细分原因只出现在受限审计，不在用户提示里）。
- **通过判据**：拦截成功且零新增效果。说明：`executive-review` 语法合法
  （schema 放行）但策略只放行主管复核队列——这一步证明拦截来自**审批比对层**
  而非格式检查。

### T-06 核验查询

- **操作**：步骤 4 输入 `SIM-5001`，点「查询工单」。
- **预期**：绿色「查询成功：1 条记录」；记录字段 `state=open`、`case_id=NS-1042`、
  `reason_code=POLICY_CONFLICT`、`target_queue=billing-supervisor-review`、
  `requested_by=user-zhou-ning`、`created_at`=T-03 执行时刻。
- **通过判据**：外部状态与写返回一致——完成由**独立读取**证明。

## 4. 拦截路径 T-07..T-10（每条开始前先点「重置演示环境」）

### T-07 拒绝后执行（用户拒绝是正常终态）

- **操作**：点「生成预览」→ 点「拒绝（记录拒绝）」→ 直接点「按当前审批执行」。
- **预期**：拒绝卡黄色「已拒绝：拒绝是正常安全终态…」，记录 ID 以 `denial-run-w14-`
  开头；执行后红色「被拦截：approval_required —— 需要有效审批后才能执行」；
  右侧「当前审批状态」当前有效状态 = denied；工单总数 = 0。
- **通过判据**：被拒审批不可执行、不可复用，零效果。

### T-08 参数缺失（schema 层拒绝）

- **操作**：点「生成预览」→ 点「批准」→ 清空 source_refs 输入框 → 点「按当前审批执行」。
- **预期**：红色「被拦截：invalid_argument —— 写请求参数不允许」
  （细分原因如「source_refs 数量必须在 1..2」只进受限审计）；工单总数 = 0。
- **通过判据**：封闭 schema 在 Host 层就拒绝，零效果。

### T-09 无审批直接执行（无审批硬门）

- **操作**：重置后**不**预览、**不**批准，直接点「按当前审批执行」。
- **预期**：红色「被拦截：approval_required —— 需要有效审批后才能执行」；
  受限审计该行细分原因含 `approval_id_missing`；工单总数 = 0。
- **通过判据**：没有审批就没有效果（模型/界面转述都不算数）。

### T-10 审批过期（可选，需要真实等待 15 分钟）

- **操作**：点「生成预览」→ 点「批准」→ 记下审批面板的过期时间 →
  等待过期时间过后（页面剩余秒数归 0）→ 点「按当前审批执行」。
- **预期**：红色「被拦截：approval_expired —— 审批已过期，请重新预览并确认」；
  工单总数 = 0。
- **通过判据**：有效期真实生效。时间紧张可跳过本条（自动化测试已用固定时钟覆盖）。

## 7. 边界与已知限制（诚实口径）

- 单用户教学会话：服务不设登录，请勿多人同时操作同一页面；
- 全部效果发生在隔离模拟工单服务（SIM-5001 起编号），不触真实系统；
- 审批/审计面板属 **restricted 审计面**（含批准载荷），截图外发前请先抹除；
- `result_unknown`（写后断连对账与补偿）、执行前撤销（revoke）留第 15 周；
- 审批 TTL 900 秒**真实计时**：会话放置超过 15 分钟后需重新预览 + 批准；
- 服务只监听本机 127.0.0.1，不做跨机器访问；测试结束可直接关闭黑色窗口。
